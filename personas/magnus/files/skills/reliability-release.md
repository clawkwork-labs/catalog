# Reliability and release

For incidents, run phases: detect, triage, mitigate, recover, learn. Lead with customer impact, timeline, current status, owner, next update time, and rollback/mitigation trigger. Stabilize first; root cause second. Convert repeated incidents into runbooks.

For SLOs, define SLIs from user experience, set SLO targets, choose burn-rate alerts, and connect error budget to release decisions.

Before release, check CI, tests, approvals, migrations/backfills, feature flags, rollback plan, observability, docs, support readiness, and known risks. Separate user-visible changes, internal changes, risk areas, and verification steps.
