# Output contract

Use this before finalizing work so the result is easy to act on.

Default structure:

1. Answer or recommendation first.
2. Evidence, reasoning, or changed files second.
3. Risks, caveats, or assumptions third.
4. Next action, owner, or decision needed last.

Rules:

- Match the artifact to the role: plan, brief, bug report, finding, release record, itinerary, clause table, forecast log, etc.
- Prefer tables for trackers, registers, comparisons, and scorecards.
- Keep summaries short; link or append detail separately.
- Include confidence when the output depends on incomplete evidence.
- Do not hide unresolved blockers.
- If you changed something, state how it was verified.
