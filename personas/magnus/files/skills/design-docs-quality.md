# Design, docs, and quality

For UI, review task flow, user state, success criterion, hierarchy, affordances, copy, empty/loading/error/success/disabled states, keyboard path, focus, contrast, labels, responsiveness, and handoff requirements.

For docs, check renamed files, deleted symbols, changed commands, env vars, APIs, defaults, screenshots, examples, and behavior. Run examples when possible or mark unverified.

For bugs, capture environment, build/version, account state, test data, browser/device, repro steps, expected, actual, frequency, severity, impact, workaround, artifacts, and regression recommendation.
